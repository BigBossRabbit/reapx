# ReapX index

The `reapx` plugin turns the user's X (Twitter) bookmarks — harvested from
their own logged-in browser, no paid X API — into namespaced, read-only
Hermes skills. **This index skill is the one that is always there from
install; everything else under the `reapx:` namespace was generated from a
bookmark the user saved.**

## What is there and how to find it

- **`reapx_status`** — the read-only state: harvest mode, last run, the
  seen-ledger counts (total seen / new last run), every registered
  `reapx:<name>` skill, the last two-track assessment, the LLM enrichment
  state, and pending review items.
- **`reapx_review`** — the item-by-item review surface: each new bookmark
  with its text, category, two-track assessment
  (integrate-into-makeup / business-opportunity) and the generated skill.
  LLM-derived opportunities land here, never silently in the ledger.
- **`skill_view("reapx:<name>")`** — every generated skill is loadable with
  its qualified name (also listed by `reapx_status` and `skills_list`).
- **`reapx_harvest`** (browser mode) / **`reapx_import`** (export mode) —
  the harvest tools (see `plugin.yaml`'s settings for the modes).

## What the categories mean

Generated skills are filed into one of 12 domains (the engine's
`references/categories.json` keyword taxonomy): bitcoin-lightning, ai-ml,
privacy-security, finance-trading, development-tools, social-media,
health-wellness, travel-exploration, voice-audio, video-streaming,
education-learning, gaming-entertainment — plus `uncategorized`.

## Two engines, honestly labeled

With `enrich: llm` (the default), the map / categorize / assess stages run
through the host LLM (`ctx.llm` — the active provider/model, zero keys in
the plugin) with the deterministic rules engine as the fallback; every item
carries `engine: "llm" | "rules"` in `reapx_review`, and keyword verdicts
always win over LLM ones. With `enrich: rules`, zero LLM calls run at all.

## When the user says…

- *"that thing I bookmarked"* / *"the tool from that tweet last week"* — it
  is probably one of these skills: `reapx_status` first, then
  `skill_view("reapx:<name>")`.
- *"what did ReapX give me?"* — `reapx_status`.
- *"check the new ones"* — `reapx_review` (default: the last run).
- *"refresh from my bookmarks"* — `reapx_harvest` (browser mode).

## Provenance + privacy

Every generated SKILL.md carries a `Generated by the reapx plugin on <date>
from x.com/<author>/status/<id>` line. All harvested data, the seen-ledger,
the registry and the generated skills live in the profile-scoped
`plugin-data/reapx/` store; nothing is uploaded anywhere (the optional LLM
enrichment sends bookmark text to the user's active provider through the
host — set `enrich: rules` for zero LLM calls).
